# 2차 보완 검토 자료 (GPT 검토용)

기준: 1차 완료 커밋 `1f29aea` → 2차 보완. 배포하지 않음.

## 1. 예약 시작·종료를 날짜만으로 저장

- 저장 형식: `reservationStart` / `reservationEnd` = `'YYYY-MM-DD'`(날짜만, 시각 미정) 또는 `'YYYY-MM-DDTHH:mm'`(행사 현지 시각) 또는 `null`.
  필드 이름과 `schemaVersion: 1`은 그대로 유지했습니다. 기존 데이터에는 시각이 포함된 형식만 있으므로 바꾸지 않고 그대로 읽습니다.
- 시각을 임의로 채우지 않습니다(00:00·23:59 없음). 날짜만 입력하면 화면에 `2026. 12. 10. (목) · 시각 미정`처럼 표시합니다.
- 입력 폼: 예약 시작·종료마다 날짜 칸과 선택 입력인 시각 칸이 따로 있습니다. 날짜 없이 시각만 넣으면 "날짜를 먼저 입력하세요."를 보여 줍니다. 덜 입력한 날짜·시각도 오류로 표시합니다.
- 예약 상태 판정(행사 시간대 기준, 위에서부터 먼저 맞는 규칙 적용):

| 조건 | 결과 |
|---|---|
| 예약 불필요 / 예약 필요 여부 확인 필요 | 예약 불필요 / 예약 확인 필요 |
| 종료 시각이 지남(종료가 시각이면 그 분까지 접수), 또는 종료가 날짜만이고 오늘이 그 다음 날 이후 | 예약 마감 |
| 행사가 종료됨 | 예약 마감 |
| 시작 시각 전, 또는 시작이 날짜만이고 오늘이 그 전날 이전 | 예약 오픈 전 |
| 시작이 **확실히 지났고** 종료가 **확실히 남음** | 예약 접수 중 |
| 그 밖(날짜만 있는 시작일·종료일 **당일** 포함) | 예약 확인 필요 |

## 2. 행사 등록·수정 초안 저장·복구

- 저장 키: `subcul-trip-planner:v1:draft:new`(새 행사), `subcul-trip-planner:v1:draft:edit:<행사 id>`(행사별 수정).
  초안을 읽을 때 저장된 종류와 행사 id가 요청한 대상과 같은지 다시 확인합니다. 그래서 다른 행사의 초안은 복원되지 않습니다.
- 입력 내용이 처음 값과 달라지면 0.4초 뒤 자동으로 저장합니다. 페이지를 숨기거나 닫거나 화면을 벗어날 때(뒤로 가기·새로고침·탭 닫기)는 즉시 저장합니다.
- 다시 열면 "저장하지 않은 초안이 있어요 (날짜 시각)" 안내와 **초안 복구 / 버리기** 버튼이 나타납니다. 둘 중 하나를 고르기 전에는 폼 입력이 막혀 있습니다.
  초안을 만든 뒤 행사가 수정됐다면 그 사실도 함께 알려 줍니다.
- 초안을 지우는 경우: 저장 완료, 버리기, 취소·메뉴 이동에서 '나가기' 확인, 행사 삭제, 샘플 모두 삭제(해당 샘플의 초안만), 전체 초기화.
  행사가 사라진 수정 초안, 30일이 지난 초안, 형식이 잘못된 초안은 자동으로 정리합니다.
- 다른 탭에서 같은 행사를 저장해 초안이 지워졌더라도, 이 탭은 페이지를 떠날 때 다시 저장합니다(2차 검증에서 발견해 수정).
- 초안이 정상적으로 저장되면 새로고침을 막는 경고창은 띄우지 않습니다. 저장 공간 문제로 초안을 저장하지 못한 경우에만 경고합니다.

## 3. 여행 기본 정보 접기 · 알림 교체 · 하단 메뉴

- 여행 요약에 "기본 정보 접기/펼치기" 버튼을 추가했습니다.
  - 접어도 여행 이름, 기간(N박 M일), 숙소 이름, 시간대 안내는 계속 보입니다.
  - 접힌 상태는 여행마다 화면 설정 키(`subcul-trip-planner:ui:trip-summary-collapsed`)에 기억하며, 내보내기 데이터에는 포함되지 않습니다.
- 알림(토스트): 성공·안내 알림 자리 1칸, 오류 알림 자리 1칸을 둡니다. 새 알림은 같은 자리의 이전 알림을 교체합니다(중첩 없음).
- 하단 메뉴 가림 점검:
  - 대상: Pixel 7, iPhone SE, iPhone 13, Galaxy S9+ 크기 × 7개 화면. 모두 Chromium 에뮬레이션입니다.
  - 결과: 마지막 콘텐츠가 하단 메뉴 위로 약 28px 떨어져 있어 가려지지 않습니다.
  - 아래쪽 안전 영역(safe area) 34px도 CDP로 흉내 내 확인했습니다.
  - 짧은 화면의 수정 폼에서 저장 바가 15px 가려지던 문제는 저장 바를 form 밖으로 옮겨 고쳤습니다.

## 4. 1차에서 건너뛴 테스트 10개와 oxlint 경고

1차 보고의 "건너뜀 10개"는 모두 `e2e/mobile-layout.spec.ts`의 **기기 전용 테스트**였습니다. 같은 파일을 모바일·데스크톱 두 프로젝트가 함께 실행하면서, 해당하지 않는 기기에서 건너뛴 것입니다.

| # | 테스트 | 건너뛴 프로젝트 | 이유 |
|---|---|---|---|
| 1 | 주요 화면에 가로 넘침이 없고 하단 메뉴가 보인다 (Pixel 7) | desktop | 모바일 전용 |
| 2 | 하단 메뉴로 모든 탭을 이동할 수 있다 | desktop | 모바일 전용 (데스크톱에는 하단 메뉴 없음) |
| 3~6 | 360px 폭: `/events`, `/events/sample_001`, `/trips`, `/manage/new` 가로 넘침 없음 + 하단 메뉴 | desktop | 모바일 전용 |
| 7 | 360px: 필터 패널을 펼쳐도 가로 넘침 없음 | desktop | 모바일 전용 |
| 8 | 360px: 대화상자가 화면 폭 안에 들어간다 | desktop | 모바일 전용 |
| 9 | 360px: 행사 등록 폼 오류 상태에서도 가로 넘침 없음 | desktop | 모바일 전용 |

- 미검증 범위: 같은 테스트가 다른 프로젝트에서 이미 통과했으므로, 1차에서 빠진 기능 검증은 없었습니다. 다만 모바일 전용 검사는 Pixel 7 한 기종에서만 실행됐습니다.
- 수정:
  - 파일을 `layout.mobile.spec.ts`와 `layout.desktop.spec.ts`로 나누고, 설정에서 해당 프로젝트에만 배정했습니다. 이제 건너뛰는 테스트는 0개입니다.
  - iPhone SE 크기 프로젝트(`mobile-small`, Chromium 엔진)를 추가해 모바일 전용 검사를 두 기종에서 실행합니다.
- 여전히 검증하지 못하는 범위: 설치된 브라우저가 Chromium뿐이라 iOS Safari(WebKit)와 Firefox 엔진, 실제 기기는 확인하지 못했습니다.

oxlint 경고(1차 보고 시점 1건, 확인해 보니 실제로는 2건이었습니다. 모두 해결해 지금은 0건입니다):
